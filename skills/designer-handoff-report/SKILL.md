# /designer-handoff-report — 완성 화면 3열(SE·16 Pro·Figma) 비교 디자이너 리포트

> 정책: git 상태 변경 금지 — checkout/switch/branch/commit/stash/push 안 한다. 작업 브랜치 유지.
> 정책: 이 스킬은 **읽기·캡처·문서 조립만** 한다. 앱 코드를 고치지 않는다(불일치를 발견해도 수정은 이 스킬의 일이 아니다 — 관찰만 적는다).
> 정책: 캡처 이미지·리포트는 **커밋하지 않는다**(레포 bloat 정책 — [[no-commit-figma-qa-artifacts]]). 전용 gitignored 핸드오프 폴더에만 쓴다.

## 무엇 — 역할 한정 (이걸 먼저 이해한다)

이 스킬은 **디자이너에게 보여줄 최종 산출물**을 만든다. **검증 스킬이 아니다.**
- **visual-verify(P3)** = Figma vs 구현을 위젯 단위로 적대 대조해 **합격/불합격** 판정(다수결). 픽셀 수정을 유발.
- **feature-runtime-qa(P4)** = 실빌드로 체크리스트/시나리오 돌려 **결함** 판정.
- **이 스킬** = 그 모든 검증이 끝나 **완성된 화면을, 반응형(작은·큰 화면)으로 캡처하고 Figma 옆에 붙여 "이렇게 나왔습니다" 하고 보여주는 리포트.** 판정·점수·수정 없음. 관찰 메모만.

그래서 이 스킬은 **루프의 맨 끝**(전 기능 개발·검증·PR 완료 후)에 한 번 돈다. 중간 Phase 에서 부르지 않는다.

## 언제

- develop-looping-process 가 **전 9기능 완료 + PR(P7 ✅)** 뒤 종단으로 라우팅했을 때. 또는 사람이 직접 "완성 화면 디자이너 보고서 만들어줘" 라고 했을 때.
- 인자(선택): 대상 기능 목록. 없으면 **완료된 전 기능**. 하나만 주면 그 기능만.

## 선행 조건 (들어오기 전)

1. 진행판 `docs/renew-guide/impl/settings/develop-looping-process-status.md` 를 읽어 **어떤 기능이 완료(P5 ✅·open_gaps=0·needs_sim=0, 또는 P7 ✅)** 인지 확인한다. 미완 기능은 "완성물"이 아니므로 리포트에서 제외하거나 "미완" 배지로 분리한다.
2. **QA 빌드/토큰 준비 여부** 확인 — visual-verify 와 동일한 QA 토큰 시드로 sim 을 띄운다(빈/로딩/성공 상태를 재현 가능하게). 준비가 안 됐으면 멈추고 알린다.
3. 시뮬레이터 2대(작은·큰)가 부팅 가능한지 확인(아래 "디바이스 타깃").
4. 조건 미충족이면 자동 진행하지 말고 무엇이 빠졌는지 보고한다.

## 디바이스 타깃 (3열의 근거)

| 열 | 소스 | 기본값 | 비고 |
|---|---|---|---|
| **작은 화면** | 시뮬레이터 빌드 캡처 | **iPhone SE (3rd generation)** | 최소 폭(375pt)에서 레이아웃 깨짐·넘침 확인용 |
| **큰 화면** | 시뮬레이터 빌드 캡처 | **iPhone 16 Pro** | visual-verify 기준 기기와 동일(일관성) |
| **Figma** | figma-sync `extract_doc` PNG | 해당 프레임 시안 | 실측 추출물(`docs/designs/**`)이 이미 있으면 재사용 |

정확한 시뮬레이터 이름이 로컬에 없으면 가장 가까운 것으로 대체하고, 리포트에 **실제 사용한 기기명**을 적는다(SE 계열이 없으면 iPhone 13 mini 등 소형으로 대체 명시). 스케일 기준 = Figma 375×812.

## 캡처 빌드 — 디버그 배너 제거 (필수, 캡처 전에)

캡처는 **반드시 `--dart-define=QA_MODE=true` 로 빌드**한다. 이 repo 는 `lib/app/app.dart` 가 QA_MODE 빌드에서 `debugShowCheckedModeBanner` 를 끈다 — dev 데이터·QA 자동로그인·marionette 구동은 그대로 두고 **우측 상단 DEBUG 리본만 사라진다**. 일반 dev 빌드(QA_MODE 없음)는 dev 플레이버라 배너가 남으니 **디자이너 리포트용으로 쓰면 안 된다**(이 배너는 기본 Flutter debug 배너가 아니라 `flavor != prod` 로 코드에 박혀 있어 빌드 모드를 바꿔도 안 없어진다 — QA_MODE 로만 꺼진다).

예:
```
flutter run --flavor dev \
  --dart-define-from-file=config/dev.json \
  --dart-define-from-file=config/dev.secrets.json \
  --dart-define=QA_MODE=true
```

**배너 확인 게이트:** 각 기기에서 **첫 화면을 찍자마자 우측 상단에 DEBUG 리본이 없는지** 확인한다. 남아 있으면 QA_MODE 가 안 들어간 빌드다 → 캡처를 멈추고 QA_MODE 를 넣어 재빌드한 뒤 처음부터 다시 찍는다. **배너가 박힌 캡처는 리포트에 넣지 않는다.**

## Figma 매칭 — 파일명을 믿지 마라 (내용으로 검증, 필수)

이 repo 의 Figma export 파일명은 **프로토타입 순서 기반**(`dm-setting-inquiry-*` 등)이라 **화면 내용과 어긋난다.** `figma_<feature>-list` 라는 파일명을 믿고 목록 행에 붙이면 엉뚱한 화면이 들어간다 — 실제로 사고가 났다(2026-07-02 문의 리포트: **목록 행에 문의 '작성' 시안, 상세 행에 문의 '홈' 시안**이 잘못 매칭됨. 진짜 목록·상세 시안은 누락).

그래서 **반드시 내용으로 매칭한다:**
1. Figma 후보를 **열어서 실제로 무슨 화면인지**(타이틀·구성요소) 눈으로 확인한다. 파일명으로 판단하지 않는다.
2. 그 Figma 를 **같은 화면의 빌드 캡처와 나란히 놓고 "같은 화면인가?"** 를 확인한 뒤에만 그 행에 넣는다(예: 목록 행 Figma 는 "내 문의 내역" 리스트여야 하고, 작성/홈 화면이면 틀린 것).
3. 대응 프레임을 못 찾거나 파일명과 실제가 다르면 그 행 Figma 열은 **"⚠️ N/A — 실제 <화면> 프레임 미확보(figma-sync 재추출 필요)"** 로 정직하게 둔다. **엉뚱한 프레임으로 채우지 않는다.**
4. 올바른 프레임이 필요하면 `figma-sync` 로 **그 화면을 지정해**(노드/프레임 내용 기준, 파일명 아님) 재추출한다.

**허위 검증 금지.** 각 행의 좌(빌드)↔우(Figma)가 같은 화면인지 실제로 눈으로 확인하지 않았으면 "codex/대조로 확인함" 같은 문구를 쓰지 마라. 확인한 행만 "확인"이라 적는다.

## 절차 (순서 고정)

캡처·Figma 추출의 **세부 기법은 재발명하지 말고** visual-verify 를 그대로 따른다 — READ: `.claude/skills/visual-verify/SKILL.md`(QA 토큰 sim 부팅·`qa_*` 키 구동·상태 전수 캡처·Figma extract_doc 레시피). 이 스킬은 거기에 **① 두 번째 디바이스(SE) 축 ② 판정 대신 3열 리포트 조립** 만 더한다.

1. **화면 목록 컴파일.** 완료된 각 기능의 화면(과 의미 있는 상태 — 빈/성공/에러/시트/입력단계)을 나열한다. 근거 = 기능별 `impl/settings/<feature>.md`·`ai_specs/<feature>.md`·`_vv-<feature>` 캡처 흔적(visual-verify 산출)·`qa_<feature>_*` 키. **webview 화면**(외부 링크)은 진입 화면만, 내부는 대상 아님.

2. **Figma 시안 확보 + 내용 매칭.** 각 화면의 매칭 프레임을 `figma-sync` extract_doc 로 PNG 추출하거나 `docs/designs/**` 기존 추출물을 재사용한다. **여기서 파일명을 믿지 말고 위 "Figma 매칭 — 파일명을 믿지 마라" 규칙대로 각 프레임을 열어 내용으로 확인**해 화면에 붙인다. 대응 프레임을 못 찾거나 내용이 다르면 그 화면 Figma 열은 "⚠️ N/A — 실제 프레임 미확보(재추출 필요)"로 두고 리포트에 남긴다(엉뚱한 프레임으로 채우지 않는다).

3. **작은 화면(SE) 캡처.** iPhone SE 시뮬레이터 부팅 → **QA_MODE 빌드 설치**(위 "캡처 빌드" — 배너 off) → **첫 스크린샷으로 DEBUG 리본 없음 확인** → `qa_*` 키(marionette 우선 → ios-simulator) 로 각 화면·상태로 이동 → 스크린샷. 파일명 규칙 `<feature>__<screen>__<state>__se.png`.

4. **큰 화면(16 Pro) 캡처.** iPhone 16 Pro 시뮬레이터에도 **같은 QA_MODE 빌드**를 설치(배너 확인) → 같은 화면·상태를 같은 경로로 이동 → 스크린샷. 파일명 `<feature>__<screen>__<state>__16pro.png`. **두 기기의 화면·상태 집합을 동일하게 맞춘다**(한쪽에만 있는 상태가 있으면 리포트에 사유 표기).

5. **리포트 조립(MD).** 아래 "리포트 구조"대로 화면마다 3열 표를 만들고, 이미지를 상대경로로 임베드한다. 각 행에 **관찰 메모**(넘침/여백/폰트/상태 차이 — 판정이 아니라 디자이너가 볼 관찰)를 한 줄. 데이터·환경 차이는 결함 아님이니 "데이터 상이"로만 표기.

6. **핸드오프 안내.** 리포트 경로를 사람에게 알린다. 이미지·리포트는 커밋하지 않는다(공유는 폴더 zip/링크로).

## 산출물 / 위치

- 리포트 + 이미지 = `docs/designs/handoff/<YYYY-MM-DD>/`. **전부 gitignored** — 커밋하지 않는다. `docs/designs/` 가 이미 .gitignore 에 있는지 확인하고, `handoff/` 가 커밋 대상으로 잡히면 .gitignore 에 추가만 하고(커밋은 사람 판단) 알린다.
- 채팅으로 경로 + 한눈에 표(기능별 화면 수·Figma 매칭률·특이 관찰 요약)만 보고한다.
- 한국어 리포트 문구는 내보내기 전 `humanize-korean` 으로 자가검열.

## 강제 / 금지 (가드)

- **디버그 배너 박힌 캡처 금지.** 반드시 `--dart-define=QA_MODE=true` 빌드로만 캡처하고, 각 기기 첫 스크린샷에서 우측 상단 DEBUG 리본이 없음을 확인한 뒤 진행한다(있으면 재빌드).
- **판정하지 않는다.** 합격/불합격·점수·수정 지시 없음(그건 visual-verify·runtime-qa 의 일). 관찰만.
- **명시적 사용자 요청 미반영은 관찰로 묻지 않는다.** 이 스킬은 검증 스킬이 아니므로 미해결 사용자 수정 요청을 리포트 꼬리 괄호·표 한 행·관찰 메모에 파묻으면 안 된다. 리포트 작성 중 명시 요청 미구현/변경을 발견하면 **리포트 최상단에 "⚠️ 미반영/변경(결정 필요)" 전용 섹션**을 만들어 요청↔반영 대조표를 맨 위에 두고, **채팅 보고 첫 줄을 블로킹 질문으로** 연다("요청 X 를 …이유로 안 하려는데 승인/반려?"). "완성 화면"으로 보고하지 않는다(AGENTS.md Explicit user request contract).
- **코드·git 무변경.** 불일치를 봐도 고치지 않는다 — 관찰로 남기고, 진짜 결함이면 사람이 P3/P6 로 돌리게 안내.
- **이미지·리포트 커밋 금지**(bloat 정책). gitignored 핸드오프 폴더에만.
- **파괴적 화면**(회원탈퇴 최종 제출 등)은 최종 제출 직전 화면까지만 캡처 — 실제 제출 누르지 않는다.
- **두 기기 화면 집합 일치.** 한쪽에만 캡처된 상태를 방치하지 말고 사유를 남긴다(캡처 누락 vs 그 기기에서 안 나오는 상태).
- **없는 프레임·없는 경로 추측 금지.** Figma 매칭 못 하면 "N/A"로 정직하게.
- **Figma 파일명 신뢰 금지 — 내용으로 매칭(위 절대 규칙).** 각 3열 행의 좌(빌드)↔우(Figma)가 **같은 화면인지 눈으로 확인**한 뒤에만 넣는다. 안 맞으면 "⚠️ N/A". 확인 안 한 매칭을 "확인함"이라 적지 않는다(허위 검증 금지).
